# T63 首页搜索行右侧的圆形配色入口

## 问题

T62 把配色入口放到了标题行右侧，但用户仍觉得它和标题、搜索是两块分开的东西：入口是 80×44 的「调色盘 + 配色」胶囊，搜索框独占下一行，视觉上多一层。

用户要求：把入口做成一个圆圈，放在搜索框右边；搜索框因此短一点，边再圆润一点（R 角加大）。

## 改法

- `HomePage` 去掉 `.home-title-row` / `.home-identity` 包裹，标题和计数直接排在 header；搜索与入口放进 `.home-search-row`。
- 搜索框：`height: 44px`、`padding: 0 16px`、`border-radius: 999px`（胶囊）；`margin-bottom: 0`；在 320 宽下实测 236px，390 下 306px。
- `FormulaColors` 新增 `iconOnly` prop：首页传 `iconOnly`，只渲染 20px 调色盘 SVG，不渲染「配色」文字；练习页仍用默认带文字版本。
- 首页入口：44×44 正圆，`border: 1px solid var(--border)`、`background: var(--surface)`、`border-radius: 50%`；与搜索框同高、同排，gap 8px。
- 入口保留 `id="browse-colors"`、`title`、`aria-label="浏览配色"`、`aria-haspopup="dialog"`、`aria-expanded`，点击仍先 `focus()` 再开 T61 弹窗。
- 320 宽下 placeholder 从长示例改为「搜索公式、别名或片段」，避免在 236px 内被硬裁。

未改：配色数据、`ColorDialog`、T61 的弹窗/tab/焦点逻辑、练习页的练习配色入口（仍有文字）、T58、T60b 的 setup/求解/计时。

## 测试

- `homeColorEntry.test.ts`：改为断言行结构、搜索框 44px 胶囊、入口 `iconOnly` 正圆 44px。
- `homeBottomHint.test.ts`：顺序改为 标题 → 计数 → 搜索 → 入口 → header 结束。
- `devicePrefs.test.ts`：首页入口断言改为 `<FormulaColors iconOnly />`。
- 全量 `npm test` 3658/53、`npm run check:data` 393、`npm run build` 通过；本轮直接提交 main `9659e05`。

## 风险

- 纯图标入口比「调色盘 + 配色」更难被发现；保留 `title` 和 `aria-label`，但真机上是否一眼看懂要用户确认。
- 320 宽搜索框变短后，长 placeholder 不可用，已换成短文案；输入后的匹配逻辑未变。
- 未真机、未微信 X5、未 iOS 安全区验证。
