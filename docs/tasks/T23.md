# T23 公式页按所选公式对齐图解，点公式不自动播放

## 背景

公式详情页有两部分显示起手：2D 图解（`CaseDiagram`）和 3D 播放器（`CubePlayer`）。

- 3D 播放器从所选公式的**逆**开始播（`Timeline(alg)`），所以选哪条公式，起手就是哪条公式的逆。
- 2D 图解原来固定用 `c`，也就是 `c.algs[0]` 的逆。

同一个情形的不同公式，起手常常不一样：前面差一个 U 或 y，或者是别的等价写法。选了备选公式以后，3D 的起手变了，2D 还停在 `algs[0]` 的起手，两者对不上。

另一个问题：点公式行会自动从头播放（`replayKey`），用户只是想看这条公式的起手，不想马上被动画带走。

## 为什么 2D 固定用 `algs[0]` 是错的

`algSolvesCase` 允许同一情形的公式在起手上有 U（OLL/PLL/CMLL 的前置 U 就是 AUF）、y 的差别，所以“能解决这个情形”不等于“起手状态相同”。数一下现有数据：240 条备选公式里，211 条的起手状态和 `algs[0]` 不同；其中真正会改变图解显示的有 OLL 95 条、CMLL 25 条、PLL 19 条（F2L 另有 23 条，在显示的前两层里也不同）。也就是说，固定用 `algs[0]` 画图解，选备选公式时多数情况下图解和 3D 对不上。

## 目标

1. 图解的起手跟着所选公式走，和 3D 播放器一致。
2. 点公式行只切换所选公式，不自动播放；播放交给播放器自己的按钮。
3. 首次进入时显示主公式的起手，也不自动播放。
4. 所选公式解决不了这个情形（自定义的错公式）时，图解不显示错起手；播放器仍然能播放这条公式本身。

## 改动

### `viewCaseFor`（`cases.ts`）

```ts
viewCaseFor(c, alg) = algSolvesCase(c, alg) ? { ...c, algs: [alg] } : c
```

抽成纯函数是为了能单测。`CasePage` 里用 `useMemo(() => viewCaseFor(c, playing), [c, playing])`，其中 `playing = selected ?? primary`。`CaseDiagram` 用 `viewCase`；标题、名称、识别、收藏、统计、学习状态仍然用 `c`。

### `viewCase` 的边界

| 情况 | `viewCase` |
| --- | --- |
| 所选公式能解决该情形 | `{ ...c, algs: [所选公式] }`，其他字段原样保留，不改原对象 |
| 所选公式就是定义公式 | 起手和 `c` 一致 |
| 解决不了该情形（自定义的错公式、别的情形的公式） | 回退到 `c` 本身（同一个对象） |
| 公式格式有误（`parseAlg` 抛错）、空串 | 回退到 `c`，不抛错 |
| 违反转动限制（LSE 里出现 R 等） | 回退到 `c` |
| F2L 前置 U（T9：F2L 不允许 pre-U） | 回退到 `c` |
| LSE 前置 U | 允许，起手随公式变化 |

`algSolvesCase` 可能抛错，`viewCaseFor` 内部用 `try/catch` 兜底。

回退到 `c` 时图解显示的是定义公式的起手，而 3D 播放器显示的是这条错公式自己的起手，两者此时是不一致的，这是有意的：宁可图解保持在一个正确的情形上，也不显示一个并不属于这个情形的状态。

### `CubePlayer` 的 `autoPlay`

- 新增 `autoPlay?: boolean`，**默认 `true`**，保持其他调用方的行为（现在只有 `CasePage` 一个调用方，已确认）。
- `alg` 变化时：永远 `seek(0)` 回到起手；只有 `autoPlay` 为 true 才接着 `runTo` 播放。
- 首次挂载永远不自动播放（沿用原来的行为，也避免开发模式下 effect 重跑误触发）。
- `CasePage` 传 `autoPlay={false}`。
- 删除了 `replayKey` prop 和 `CasePage` 里的 `replayKey` state；`played` ref 简化成只记上一次的 `timeline`（`shown`）。代价：同一条公式连点两次不会再重播，这正是想要的。

### 公式行

点公式行只 `setSelected(alg)`。按钮的 `aria-label` 从“播放 …”改成“查看这条公式的起手 …”，不再出现“播放”二字。

## 坑

- `useMemo` 必须放在 `if (!c) return` 之前（hooks 顺序），所以 `primary` 和 `playing` 也移到了前面，用 `c ? … : ''` 兜底。
- `CaseDiagram` 每次渲染都直接从传入的情形算颜色，没有按 `c.id` 做缓存，所以换成 `viewCase` 就会跟着变；以后如果给它加缓存，缓存键要包含 `algs[0]`。
- 判断“起手不同”要比 `caseState`，不能比“解不解得了”：解得了只说明等价，不说明起手相同。
- 起手不同不等于图解不同：F2L 只显示前两层，很多差别在没显示的顶层，图解不变是正常的。
