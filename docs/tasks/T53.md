# T53 底部 tab 返回栈 + 滚动位置恢复

## 问题

1. 底部四个 tab 用 `NavLink` 默认 push：详情 → 我的 → 公式后，系统返回落到“我的”，不是公式页的上一级。
2. 详情页 `useScrollTop` 每次回顶；`SetPage` 的 `useScrollMemory` 只覆盖自己；首页、详情返回时滚动位置丢失。

## 行为

- 底部 tab 的 `replace` 规则见下面“T53-fix”（第一版是四个 tab 全部无条件 `replace`，会把首页/组页从历史里替换掉，已修正）。详情 → 我的 → 公式：回到详情；系统返回落到进入详情前的页面（通常 `/set/…`，没有则首页）。
- 新打开页面（PUSH，如从组页点一张卡片）：回顶部。
- 返回或切 tab（POP / REPLACE）：恢复该 pathname 上次的滚动位置。
- 选择公式页（`/`、`/set/…`）恢复滚动和现有筛选；详情页恢复滚动。
- T51 的“公式”tab 目标不变（公式区回 `/`，其他区回 `lastCaseId`）；T49 选中记忆不动。
- 只存内存 `uiState`，刷新重置；不写 localStorage。

## 改动

- 新增 `src/lib/scrollRestoration.ts`：`scrollKey(pathname)`、`shouldRestoreScroll(navType)`、`useScrollRestoration()`（`useLocation` + `useNavigationType`，导航时在 `useLayoutEffect` 里 `scrollTo`，页面内持续记录 `scroll`，离开时再存一次）。
- `src/App.tsx`：`<HashRouter>` 里加 `<ScrollRestoration />`（在 `Nav` 之后、`<main>` 之前）；`NavLink` 的 `replace` 规则见 T53-fix。T51 的 `formulaTo` 逻辑没动。
- `src/pages/CasePage.tsx`：删掉 `useScrollTop`；T51 的 `lastCaseId` effect 保留。
- `src/pages/SetPage.tsx`：删掉 `useScrollMemory`；筛选的 `getUi/setUi` 保留。
- `uiState.ts` 里的 `useScrollMemory`、`useScrollTop` 没删，现在没人用（不在允许改的文件里）。

### 和任务写法不同的一处：离开时存哪个位置

任务写的是“cleanup 时再 `setUi` 当前 scrollY”。我最初改成存“最近一次 scroll 事件的位置”，浏览器里测发现不对：scroll 事件按帧派发，会比手指落后（后台页面里甚至不派发），详情 → 我的 → 公式时详情的位置丢成 0。清理里现读 `window.scrollY` 也不行：清理发生在新页面 DOM 换上之后，可能被新页面更短的高度截断。

最终做法：在 `ScrollRestoration` 每次 **render 阶段**（旧页面 DOM 还在）读一次 `window.scrollY` 放进 ref，离开时存这个值。`scroll` 监听仍保留（持续记录）。

## 测试

- 新增 `src/lib/scrollRestoration.test.ts`（8 项，T53-fix 后 9 项）：`scrollKey` 对 `/`、`/set/oll`、`/case/oll-27` 的 key，各页面 key 互不相同；`shouldRestoreScroll` POP true、REPLACE true、PUSH false；源码接线：`App` 有 `ScrollRestoration`；`replace` 规则见 T53-fix；T51 目标不变；`CasePage` 无 `useScrollTop`、`lastCaseId` effect 还在；`SetPage` 无 `useScrollMemory`、筛选读写还在；hook 里用 `useLocation`/`useNavigationType`/`useLayoutEffect`、不碰 localStorage、清理里不现读 `window.scrollY`。
- `src/lib/nav.test.ts` 里只更新了一个精确字符串（见 T53-fix），其余断言没放松。

## T53-fix：返回栈规则

### 问题

第一版四个 `NavLink` 全部无条件 `replace`：首页 → 我的 会把首页从历史里替换掉，我的 → 公式 回到详情后，系统返回会退出或回到上一站，而不是首页。上面“没有 `/set` 时回首页”的承诺不成立。

### 改法（只改 `App.tsx` 的 `Nav`）

```
const inCase = pathname.startsWith('/case/');
const inTab = pathname === '/search' || pathname === '/practice' || pathname === '/me';
公式：  <NavLink to={formulaTo} replace={!inFormulas} …>
其他三个：<NavLink … replace={inCase || inTab} className="nav-item">
```

- 详情 → 我的/搜索/练习：replace，详情不留在历史；
- 我的/搜索/练习 → 公式：replace，tab 不留在历史；
- 首页/组页 → 我的/搜索/练习：push，保留首页/组页；
- tab 与 tab 之间：replace，不叠历史。

### 测试

- `scrollRestoration.test.ts`：不再断言所有 `NavLink` 都有裸 `replace`；改为断言 `inCase`/`inTab` 的定义，公式链接是 `replace={!inFormulas}`，其余三个是 `replace={inCase || inTab}`，并且没有无条件的裸 `replace`。原来的一条拆成了两条，所以总数 3301（+1）。
- `nav.test.ts`：精确字符串改成 `<NavLink to={formulaTo} replace={!inFormulas} className=`。

### 浏览器里补测（独立 worktree，390×844，每条都先整页刷新让内存状态清空）

1. 首页 → 我的 → 公式 → 返回：首页。
2. 组页 → 详情 → 我的 → 公式 → 返回：组页（详情滚动 300 恢复、组页滚动 700 恢复）；再返回：首页。
3. 组页 → 详情 → 我的 → 搜索 → 公式 → 返回：组页；历史比进入详情时多 0 条。
4. 首页 → 我的 → 搜索 → 公式 → 返回：首页；首页 → 练习 → 搜索 的 tab 之间切换历史多 0 条。
5. 滚动位置仍恢复（见 2）。

没有验证：真机（iOS 侧滑返回、Android 系统返回）。一个小遗留：没有任何详情记录时，首页 → 我的 → 公式 会用 `/` 替换“我的”，历史里有相邻两个首页，返回仍是首页，只是多按一次返回才会离开。
