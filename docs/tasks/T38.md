# T38 全局禁用点击高亮，保留键盘焦点

## 范围与基线

- 只改 `src/styles.css`，另新增本报告。未改导航 active 颜色、布局、圆角、滑块，也未改源码逻辑、数据或测试。

## 问题与修正

手机点按底部导航时的短暂浅蓝块属于浏览器 tap highlight，与站点的橙色 active 滑块不同。

在原 html 规则中加入 `-webkit-tap-highlight-color: transparent`，全局禁止浏览器点按叠层。390 宽浏览器读取四个导航链接的计算样式，全部继承为 `rgba(0, 0, 0, 0)`，所以本轮没有再加 `a, button` 覆盖。

增加 `:focus:not(:focus-visible) { outline: none; }`；保留原 `:focus-visible` 的 2px accent 描边及 2px offset。鼠标点击不留框，键盘导航仍有可见焦点。

## 实际浏览器检查（390 × 844）

使用桌面内置浏览器的 390 宽视口，依次按住“练习”“搜索”“我的”各约 1 秒再松手：页面跳转正常。松手后的画面未见浅蓝残留或鼠标焦点框，原橙色 active 滑块仍在。

- 四个 `.nav-item` 的 `-webkit-tap-highlight-color` 均为透明。
- 鼠标点“我的”后：`:focus-visible` 为 false，outline 为 none；导航链接本身背景仍为透明，橙色滑块照旧。
- 随后按 Shift+Tab 到“练习”：`:focus-visible` 成立，计算 outline 为 `rgb(181, 72, 15) solid 2px`，outline-offset 为 2px，截图可见橙色焦点框。
- document 的 clientWidth / scrollWidth 都为 390，无横向溢出。
- 截图保存在会话可视化目录：`t38-nav-click-390.png`、`t38-nav-keyboard-390.png`，不纳入仓库。

这是实际桌面浏览器窄屏操作，**不是触屏真机验收**；未独立截到指针按下期间的瞬态叠层。透明属性继承已确认，真手机 Safari/Chrome 的点按闪块仍需用户复核。若某一浏览器不继承，再按任务范围补链接/按钮规则。
