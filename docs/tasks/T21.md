# T21 练习会话持久化、计时持续、屏幕常亮

## 背景

安卓 Chrome 线上 a45238a 真机测试发现：

- 练习中点「查看详情」再返回、或切到别的 tab 再回练习，会话丢失（题目、本次题数、计时全没了）
- 练习页按系统返回直接退出，计时不保留
- 计时中切后台 10 秒回来，用时把后台时间也算进去（跳变）
- 练习时屏幕会自动熄灭

根因：`PracticePage` 的 `practicing`、`Session` 状态都在组件里，`App.tsx` 按 `pathname` 给 route 加 `key`，路由一变整棵卸载；没有 Wake Lock。

**需求修订（第二版）**：用户要的不是“离开就暂停”，而是开始计时之后，除非应用被系统清掉，计时一直走。切路由、切后台期间计时照常走，回来用时包含离开的时间，这是预期，不是跳变。只有重载、冷启动、进程被杀，计时才停在离开的那一刻。

## 目标

1. 会话存 localStorage 的 `mofang.practice.v1`，结束时清空；过期、损坏、题目 id 不存在时丢弃。
2. `PracticePage` 挂载时有可恢复的会话就直接进练习，不先闪设置页。
3. 计时中离开页面（点「查看详情」、切 tab、系统返回）或切后台：计时不停，回来按原起点继续算。
4. 重载、冷启动、进程被杀之后回来：暂停，用时停在最后一次保存的时刻，不含进程不在的时间；点屏幕继续。
5. 新增 `paused` 阶段；`ready/running/done` 的行为不变。
6. Wake Lock 只在计时中且页面可见时申请，停止、暂停、退出、隐藏时释放；不支持或失败静默降级。
7. 不改练习算法、权重、`userStore` 数据结构；`addTime` 仍只在停表时调用一次。

## 设计

### 计时状态机（`practiceSession.ts`，纯函数，不依赖 React）

- 计时用 `Date.now()`（epoch ms）。`Timer = { phase, elapsedMs, runningSince }`，`elapsedMs` 是 `runningSince` 之前已累计的毫秒数，当前用时 = `elapsedMs + (now - runningSince)`。
- 因为用的是挂钟差值，页面在后台、被卸载期间计时都在“走”，回来时一次算出来，所以用时自然包含离开的时间。
- `startTimer`：ready → running，从 0 开始。`stopTimer`：running → done。`resumeTimer`：paused → running，保留已累计用时。
- `freeze`：把用时结算进 `elapsedMs`，变成 paused。现在**只在读取时用**：重载或冷启动恢复一个 running 会话时，按保存时刻冻结。页面离开、切后台、卸载都不再冻结。

### 判断“同一文档”：`DOC_ID`

- 模块加载时生成 `DOC_ID`（时间戳加随机串）。会话里存 `docId`。
- 重载、冷启动会重新加载模块，`DOC_ID` 变了；只是切路由或切后台，模块还在，`DOC_ID` 不变。
- 不能用 `sessionStorage` 判断：它在重载后还保留，分不出“同一文档”。

### 读取规则（`parseSession(raw, now, validId, docId)`）

| 保存的阶段 | docId | 结果 |
| --- | --- | --- |
| running，`runningSince` 是数字 | 与当前相同 | 保持 running，`runningSince` 原样，用时包含离开的时间；**不受 2 小时过期限制** |
| running，`runningSince` 不是数字（数据异常） | 相同 | 按下一行处理 |
| running | 不同或缺失 | 按 `savedAt` 冻结成 paused，用时停在保存时刻 |
| paused、done、ready | 任意 | 原样恢复 |

- 过期：超过 2 小时丢弃，**唯一例外**是上表第一行（同一文档的 running）。paused、done、ready 即使是同一文档也按 2 小时丢弃。
- 其他一律丢弃：JSON 坏了、字段类型不对、题目 id 不存在、范围为空。范围里个别 id 已不存在（数据更新过）只丢那几个，剩下为空才放弃。
- `loadSession` 读到无效会话时顺手清掉存储。

### 写入时机

页面（`PracticePage`）负责这些：

- 题目、计时状态、题数变化时存一份。
- `hidden`（切后台）、`pagehide`、组件卸载时各存一次当前快照。这些时机**只保存，不改计时状态**，不 `setTimer`。

心跳在 `practiceSession.ts` 里，**模块级**，不属于任何组件：

- `saveSession` 写入 `phase === 'running'` 时确保有一个 4 秒的 interval；写入其他阶段、`clearSession` 时停掉。
- 每一拍是纯函数 `touchRunning(storage, now, docId)`：存储里的会话还是 running，就只把 `savedAt` 改成现在，`runningSince`、`elapsedMs` 等其他字段不动，返回 true；读不到、JSON 坏了、不是 running、写入失败返回 false，心跳随即停止。
- 心跳只刷新**自己这个文档**写的会话（`docId` 相同）。别的标签页或已死掉的文档写的会话不碰，免得替它续命。
- 没有 `window`（node 测试）不启动 interval，所以测试里不会起真的定时器。
- 心跳不跟着练习页走：切到「我的」「查看详情」等页面，练习页卸载了，心跳照常拍。这样之后刷新或进程被杀，冷启动按最后一次 `savedAt` 冻结，用时包含离开练习页之后的时间。
- 后台标签页会被浏览器节流，所以不保证严格 4 秒；冷启动最多丢一个节流周期。
- 第二版曾把心跳放在 `Session` 的 `useEffect` 里，页面一卸载心跳就停了，之后冷启动会丢掉离开练习页之后的全部时间（可能几分钟），现已改掉。
- 点「结束」或「放弃」时清空，之后不再写入（`endedRef` 防止卸载时又把它写回去）。
- localStorage 不可用或抛异常时静默降级。

### 恢复和提示

- 恢复入口在 `PracticePage` 的 `useState` 初始化里，同步读取，所以第一帧就是练习界面。
- 恢复横幅“已恢复上次练习”加“放弃”，**只在恢复出来的阶段不是 running 时显示**。同一文档里切路由回来恢复 running 是无感的，不提示。第一次点屏幕后横幅消失。
- `paused` 提示“已暂停，点屏幕或按空格继续”；点屏幕走 `click`（和开始、下一题一样），不会在滑动时误触。停表仍然用按下即响应的 `pointerdown`，只在 running 时生效。

### 屏幕常亮（`wakeLock.ts`）

- `createWakeLock(nav?)`，`navigator` 可注入。`acquire()` 返回是否成功，不抛异常；`release()` 没持有时什么也不做。
- 申请是异步的：申请还在路上就被释放，到手后立刻放掉；重复申请只请求一次；系统自己释放（页面隐藏等）后同步状态，可以重新申请。
- `PracticePage` 里按 `phase === 'running' && document.visibilityState === 'visible'` 同步：切后台会释放，回到前台会重新申请，计时本身不受影响。组件卸载也会释放，同一文档回来恢复 running 时再申请。

## 边界

- 冻结 0 ms：刚开始计时就冻结，用时为 0。
- 冻结跨小时：纯函数如实结算，不截断；冷启动时不同文档的会话超过 2 小时直接丢弃。
- 同一文档的 running 超过 2 小时仍然有效，用时一直累计到现在。
- `runningSince` 为 null 的 running（数据异常）：按冻结处理，用时不变；如果同时超过 2 小时则丢弃。
- 缺 `docId`（旧数据）或 `docId` 不是字符串：按“不是同一文档”处理。
- 时钟倒退：按 0 处理，用时不会变负。
- 非 running 阶段带着 `runningSince`：读取时忽略。
- 同一次触摸里 `pointerdown` 停表后随后的 `click` 不再前进，沿用原来的 `skipClick`。

## 坑

- 第一版把“离开页面”理解成“暂停”，在 hidden、pagehide、卸载时都冻结，这与用户想要的相反。判断标准是“应用有没有被系统清掉”，不是“页面有没有离开”。
- 区分“同一文档”不能用 `sessionStorage`（重载后还在），要用模块级的 `DOC_ID`。开发时热更新替换模块也会换 `DOC_ID`，所以改了 `practiceSession.ts` 之后，开发服务器里正在计时的会话会变成暂停，这是预期。
- 周期保存只能少算不能多算：进程被杀后冷启动按最后一次保存的时刻冻结，最多少算一个保存周期（4 秒），不会把死掉的时间算进去。
- 同一文档的 running 不受 2 小时限制，否则人把练习挂着去忙别的、两小时后回来，会话会被丢掉，和“计时一直走”矛盾。
- 卸载时的保存要放在 effect 的清理函数里，并用 `endedRef` 区分“正常结束”和“被路由卸载”，否则点「结束」清掉的会话会被卸载时又写回去。
- 开发环境的 StrictMode 会让 effect 多跑一次，所以恢复入口只做读取，不能有别的副作用。
- 心跳放在组件的 `useEffect` 里是个坑：切到别的页面练习页卸载，心跳就停了，之后冷启动会丢掉离开练习页之后的全部时间，不是“最多一个周期”。心跳必须是模块级的，和组件生命周期无关。
- 模块级心跳要用 `docId` 限制只刷新自己文档写的会话，否则一个标签页的心跳会替另一个已经死掉的文档续命，冷启动时反而多算了时间。
- 后台标签页的 interval 会被浏览器节流，所以不能写成“最多丢 4 秒”，只能说最多丢一个节流周期。
