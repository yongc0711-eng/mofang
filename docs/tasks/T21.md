# T21 练习会话持久化、计时暂停、屏幕常亮

## 背景

安卓 Chrome 线上 a45238a 真机测试发现：

- 练习中点「查看详情」再返回、或切到别的 tab 再回练习，会话丢失（题目、本次题数、计时全没了）
- 练习页按系统返回直接退出，计时不保留
- 计时中切后台 10 秒回来，用时把后台时间也算进去（跳变）
- 练习时屏幕会自动熄灭

根因：`PracticePage` 的 `practicing`、`Session` 状态都在组件里，`App.tsx` 按 `pathname` 给 route 加 `key`，路由一变整棵卸载；计时用 `performance.now()` 差值，后台 rAF 暂停，回来一次性补上；没有 Wake Lock。

## 目标

1. 会话存 localStorage 的 `mofang.practice.v1`，2 小时过期，结束时清空；过期、损坏、题目 id 不存在时丢弃。
2. `PracticePage` 挂载时有未过期会话就直接进练习，不先闪设置页；顶部提示“已恢复上次练习”，提供“放弃”。
3. 离开页面（点「查看详情」、切 tab、系统返回）和 `visibilitychange=hidden` 时，正在计时就先冻结用时再保存；恢复后是暂停，点屏幕才继续。
4. 新增 `paused` 阶段；`ready/running/done` 的行为不变。
5. Wake Lock 只在计时中且页面可见时申请，停止、暂停、退出、隐藏时释放；不支持或失败静默降级。
6. 不改练习算法、权重、`userStore` 数据结构；`addTime` 仍只在停表时调用一次。

## 设计

### 计时状态机（`practiceSession.ts`，纯函数，不依赖 React）

- 计时用 `Date.now()`（epoch ms）。`Timer = { phase, elapsedMs, runningSince }`，`elapsedMs` 是 `runningSince` 之前已累计的毫秒数，当前用时 = `elapsedMs + (now - runningSince)`。
- `startTimer`：ready → running，从 0 开始。`stopTimer`：running → done，用时定格。`resumeTimer`：paused → running，保留已累计用时，`runningSince` 取当前时刻。
- `freeze`：正在计时就把用时结算进 `elapsedMs`，变成 paused，`runningSince` 置空；其他阶段原样返回同一个对象。
- 离开页面时先冻结，所以后台时间不会算进去，也不依赖后台 rAF 是否还在跑。

### 持久化

- 字段：`poolIds`、`question {id, alg, scramble}`、`phase`、`count`、`elapsedMs`、`runningSince`、`savedAt`。
- 写入时机：题目、计时状态、题数变化时都存一份（崩溃也能恢复）；`hidden`、`pagehide`、组件卸载时先冻结再存；点「结束」或「放弃」时清空，之后不再写入。
- 读取（`parseSession` / `loadSession`）：过期（超过 2 小时）、JSON 坏了、字段类型不对、题目 id 不存在、范围为空都返回 null，并清掉存储。范围里个别 id 已不存在（数据更新过）只丢那几个，剩下为空才放弃。
- 保存时还在计时的会话，读取时按保存时刻冻结成 paused，所以人不在的时间不算。
- 恢复入口在 `PracticePage` 的 `useState` 初始化里，同步读取，所以第一帧就是练习界面，不闪设置页。
- localStorage 不可用或抛异常时静默降级。

### 屏幕常亮（`wakeLock.ts`）

- `createWakeLock(nav?)`，`navigator` 可注入。`acquire()` 返回是否成功，不抛异常；`release()` 没持有时什么也不做。
- 申请是异步的：申请还在路上就被释放，到手后立刻放掉；重复申请只请求一次；系统自己释放（页面隐藏等）后同步状态，可以重新申请。
- `PracticePage` 里按 `phase === 'running' && document.visibilityState === 'visible'` 同步。

### 页面（`PracticePage.tsx`）

- `Session` 接收 `restore`；有恢复数据时用其中的题目、题数、用时作为初始状态，阶段不会是 running。
- `paused` 提示“已暂停，点屏幕或按空格继续”；点屏幕走 `click`（和开始、下一题一样），不会在滑动时误触。停表仍然用按下即响应的 `pointerdown`，只在 running 时生效。
- 顶部“已恢复上次练习”加“放弃”，第一次点屏幕后消失；“放弃”和“结束”都清掉会话。

## 边界

- 冻结 0 ms：刚开始计时就冻结，用时为 0。
- 冻结跨小时：纯函数如实结算，不截断；超过 2 小时的会话在读取时直接丢弃，不会恢复出一个很大的用时。
- `runningSince` 为 null 的 running（数据异常）：不加时间，冻结成 paused。
- 时钟倒退：按 0 处理，用时不会变负。
- 非 running 阶段带着 `runningSince`：读取时忽略。
- 同一次触摸里 `pointerdown` 停表后随后的 `click` 不再前进，沿用原来的 `skipClick`。

- 控制台没有报错。

## 真机未测项（需要用户在安卓 Chrome 上确认）

- 计时中点「查看详情」再返回：题目、题数、用时都在，状态暂停；点屏幕继续。（桌面上用切路由模拟过，没有用真实的“查看详情”入口，该入口只在停表后出现。）
- 计时中切后台 ≥10 秒：回来用时不变；点屏幕继续。（桌面上用模拟的 `visibilitychange` 验证，没有测真实的系统切后台。）
- 计时中切首页或公式组再回练习：同上。
- 点「结束」后再进练习：设置页，旧会话不再出现。
- 刷新页面：会话恢复（暂停）。
- 运行中 3 分钟不熄屏；停止后恢复系统行为。（桌面没有熄屏行为，只验证了调用；真实的 Wake Lock 是否生效要真机看。）
- 系统返回键直接退出练习页再回来：会话在。

## 坑

- 后台时 rAF 会暂停，所以不能靠计时循环来累计用时；离开前必须先冻结，用 `Date.now()` 算差值。
- 保存时还在计时的会话，读取时要按 `savedAt` 冻结，而不是按“现在”，否则人离开的时间会被算进去。
- 卸载时的保存要放在 effect 的清理函数里，并用 `endedRef` 区分“正常结束”和“被路由卸载”，否则点「结束」清掉的会话会被卸载时又写回去。
- `hidden` 时除了存一份冻结的快照，还要把界面状态也改成 paused，否则回来看到的还是“计时中”，但实际已经停了。
- 开发环境的 StrictMode 会让 effect 多跑一次，所以恢复入口只做读取，不能有别的副作用。
