# T16 真手机验收清单

## 背景

在 T1–T65 开发过程中，3D 魔方手势（`CubeScene.ts`）、练习页触摸计时与防误触（`PracticePage.tsx`）、Service Worker 离线缓存及 iOS 底部安全区（`safe-area-inset-bottom`）均仅通过桌面鼠标、无头浏览器 CDP 视口或单测替身验证，尚未在真实手机硬件与移动浏览器上逐项实测。

本文件提供真机逐项验收清单。**验收过程本身不修改代码**；实测发现的任何异常按文末规则记录并拆分为独立修复任务。

## 目标

- 在三类目标视口/真机环境下，逐项验证 T16 规定的 6 大核心体验：
  1. **3D 手指拖动**
  2. **连点两下（双击）回正**
  3. **练习页滑动不误触**
  4. **断网离线使用**
  5. **发热与卡顿表现**
  6. **iPhone 底部安全区与悬浮底栏**
- 留存真实设备的实测结论（通过 / 失败 / 现象数据）。

## 允许改

- `docs/tasks/T16.md`（仅记录实测结果；发现 bug 时另建新任务，不在 T16 内改源码）

## 非目标

- 不在本任务中顺手调整外观、圆角或间距。
- 不修改任何 `src/` 代码、`SET_RULES` 或现有测试。

## 逐项验收清单

### 1. 3D 手指拖动（公式详情页 & 试转页）

- **前置条件**
  - 打开线上站点 `https://yongc0711-eng.github.io/mofang/`（或局域网 dev 服务）。
  - 分别进入任意公式详情页（如 `#/case/pll-Ua`）和底栏「试转」页（`#/search`），等待 3D 魔方加载完成。
- **操作步骤**
  1. 单指按住 3D 魔方画布（`.player-stage` / `.sandbox-stage`），向左右水平拖动、向上下垂直拖动、画圈连续拖动。
  2. 手指从画布内按下后，滑出画布边界外再继续移动并松手。
  3. 在魔方自动播放转动过程中（点播放键后），单指拖动魔方改变观察视角。
  4. 点击画布左上角「只看相关的块」或右上角倍速按钮（`0.5x`–`2x`）。
- **预期结果**
  - 手指在画布上上下左右拖动时，**只旋转 3D 魔方，页面本身绝不发生上下滚动或左右橡皮筋回弹**（`touch-action: none` 生效）。
  - 水平拖动绕竖轴旋转方向符合直觉，垂直俯仰有上下限（`±1.45 rad`）不会把魔方翻倒失控。
  - 手指滑出画布外仍能保持指针捕获（`setPointerCapture`），松手后正常结束拖拽，不会卡在拖拽态。
  - 左上角/右上角悬浮按钮可正常点击，不与 3D 拖拽互相抢事件。
- **实际结果记录栏**
  - [ ] **320 矮小屏**（`player-stage` 高 164px / 试转 `180px` 空间是否够拖、有无误滚页面）：`[ 待填：通过 / 失败 + 现象 ]`
  - [ ] **390 主流屏**（单手拇指拖拽跟手度、播放中拖拽表现）：`[ 待填：通过 / 失败 + 现象 ]`
  - [ ] **iPhone**（Safari 左滑/右滑边缘返回手势与画布拖拽是否冲突）：`[ 待填：通过 / 失败 + 现象 ]`

### 2. 连点两下（双击）回正

- **前置条件**
  - 在公式详情页（如 `#/case/oll-27`）或「试转」页，先用手指将 3D 魔方拖离默认视角（例如转到底面或背面朝前）。
- **操作步骤**
  1. 用单指在 3D 画布同一位置快速连点两下（两次点击位移 `< 10px`，间隔 `< 350ms`）。
  2. 测试慢速点两下（间隔明显大于半秒）或边拖动边快速点按。
- **预期结果**
  - 快速连点两下后，魔方立即回到默认等轴视角（露出 U 顶、F 左前、R 右前，与 2D 图解朝向一致）。
  - 连点两下时**不触发手机浏览器的页面双击放大（double-tap zoom）**，也不选中页面文字。
  - 慢速点击或拖动后紧接着单点一次，不会误触发视角重置。

### 3. 练习页滑动不误触与按压计时

- **前置条件**
  - 进入底栏「练习」页（`#/practice`），点击「开始练习」，等待题目打乱准备完成（处于 `ready` 阶段）。
- **操作步骤**
  1. **长按准备与开始**：单指按住 `.practice-pad` 计时面板保持 1 秒以上，观察界面；然后松手。
  2. **按住滑出面板松手**：下一题 `ready` 时，按住面板，手指滑到面板外再松手。
  3. **按住时滑动手指**：在面板内按下并上下左右滑动手指，观察页面是否滚动、是否弹出系统菜单。
  4. **按住时切后台/锁屏中断**：在 `ready` 阶段按住面板不放，另一只手切到后台（或上滑回主屏）再切回浏览器，观察是否误开始计时。
  5. **停止与下一题防连跳**：`running` 计时中单指点按面板停止（进入 `done`），确认松手时不会直接跳到下一题；在 `done` 状态点击「查看详情」链接。
  6. **短屏页面滚动**：在 `done` 阶段（显示结果、公式与统计，内容超出首屏时），从 `.practice-pad` 外侧（顶部「‹ 结束」栏或页面左右留白处）上下滑动页面。
- **预期结果**
  - 按住期间面板变为橙色高亮（`data-pressing="true"`），提示「松开开始」，计时器保持 `0.00` 不提前走表；**长按不弹出系统复制/搜索菜单、放大镜或文字选中**（`-webkit-touch-callout: none`、`user-select: none`）。
  - 松手瞬间才开始走表；滑出面板外松手同样能正常开始。
  - 在面板内滑动不会带动页面上下滚动（`touch-action: none`）；但切后台/系统打断（`pointercancel` / `visibilitychange`）会立即清除按下态，返回后不会自动走表。
  - `running` 按下即停表，`pointerup` 不误触发下一题；点击面板内的「查看详情」能正常跳转，不触发下一题。
  - 当内容超出一屏时，手指从面板外侧顶部/边缘区域可以正常上下滚动页面。
- **实际结果记录栏**
  - [ ] **320 矮小屏**（重点确认 `done` 状态下能否从面板外侧顺畅滚动看到底部区域，且面板高度不跳动）：`[ 待填：通过 / 失败 + 现象 ]`
  - [ ] **390 主流屏**（按住/松手灵敏度、长按无系统菜单、停表不连跳）：`[ 待填：通过 / 失败 + 现象 ]`
  - [ ] **iPhone**（iOS 长按 callout/放大镜是否彻底抑制、上滑切后台是否安全取消按压）：`[ 待填：通过 / 失败 + 现象 ]`

### 4. 断网离线使用（PWA & Service Worker）

- **前置条件**
  - 手机连网状态下首次打开 `https://yongc0711-eng.github.io/mofang/`，浏览首页，随便点开一个公式详情页（触发 Three.js 动态 chunk 加载），确认 Service Workers 已 activated（完成了 precache）。
- **操作步骤**
  1. 开启手机**飞行模式**（同时关闭 Wi-Fi 与蜂窝数据）。
  2. 彻底刷新当前页面（或关闭浏览器标签页后重新从书签/主屏幕图标打开站点）。
  3. 断网状态下依次操作：
     - 首页搜索框输入 `Ua` 或 `Sune` 筛选；
     - 进入此前**未点开过**的公式组（如 CMLL、LSE）及任意详情页，拖动并播放 3D 魔方；
     - 修改学习状态（未学/学习中/已掌握）、点亮收藏、添加一条自定义公式；
     - 进入「练习」页完成 3 道题（含求解器生成 setup 与计时记录）；
     - 打开「配色」弹窗切换 CFOP / 桥式底色；
     - 进入「我的」页查看统计并导出备份。
- **预期结果**
  - 断网刷新或冷启动后页面正常秒开，不出现浏览器恐龙/断网报错页。
  - 所有路由、254 条公式数据、2D 图解、3D 播放器（含 `CubeScene` 动态分包）、练习求解器均正常工作，无白屏或加载失败提示。
  - 断网下修改的进度、收藏、自定义公式、练习成绩在再次刷新后依然保留在 `localStorage` 中。

### 5. 发热、卡顿与常亮表现

- **前置条件**
  - 手机电量充足（非低电量强制降频模式），关闭后台大型游戏。
- **操作步骤**
  1. **3D 连续渲染与切换**：在公式详情页开启 `2x` 或 `1x` 播放，连续切换不同公式、反复切换「魔方表面（UV 亮面 / 哑光）」和配色，并在「试转」页连续快速点击转法键 3–5 分钟。
  2. **多页面往返内存释放**：在「列表 → 详情页（加载销毁 3D）→ 试转页 → 练习页」之间往返切换 15 次以上。
  3. **练习连续出题与常亮**：在「练习」页连续练习 10–15 分钟（验证 `prepareSetup` 求解耗时与 `WakeLock` 屏幕常亮：计时 `running` 期间不触碰屏幕，观察超过手机自动锁屏时间后屏幕是否保持常亮；停表或退出后是否恢复正常锁屏）。
- **预期结果**
  - 3D 转动动画与导航切换维持流畅（无明显掉帧、卡死或 WebGL context lost 报错「这台设备无法显示 3D 魔方」）。
  - 机身仅有正常温升，无明显发烫或触发浏览器崩溃重载。
  - 练习出题（`prepareSetup`）响应迅速，无长耗时假死；支持 WakeLock 的浏览器在 `running` 阶段保持屏幕常亮。

### 6. iPhone 底部安全区与底栏避让

- **前置条件**
  - 使用带底部小黑条（Home Indicator）的全面屏 iPhone（并在 320 / 390 普通设备上对照检查悬浮胶囊底栏）。
- **操作步骤**
  1. 在 Safari 正常模式（底栏展开 / 滚动后地址栏收起两种状态）及「添加到主屏幕」全屏模式下，分别查看：**首页**、**公式组列表页**、**公式详情页**、**试转页**、**练习页**、**我的页**。
  2. 将列表页、详情页、「我的」页滚动到最底部。
  3. 在详情页展开「辅助输入键盘」（`.alg-keyboard`），观察底部按键是否被悬浮底栏或安全区遮挡。
  4. 点击悬浮底栏的四个 tab（「公式」「试转」「练习」「我的」），测试点击热区是否紧贴屏幕最底端导致误触系统上滑横条。
- **预期结果**
  - 手机悬浮胶囊导航（`.nav`）底部留有 `max(12px, env(safe-area-inset-bottom))` 间距，**不与 iPhone 底部 Home Indicator 横条重叠**。
  - 各页面滚动到底部时，最后一行内容/按钮均可完整滚到胶囊导航上方（`main` 的 `padding-bottom` 充足），不被悬浮底栏遮挡。
  - `320×640` 下首页五张方法卡（F2L/OLL/PLL/CMLL/LSE）及试转页「撤销/复原」按钮全部位于底栏上方，无横向滚动条（`scrollWidth === innerWidth`）。

## 失败后如何记录与转成新任务

真机验收过程中如果发现任何未通过项，**不要在 T16 里直接改代码**，按以下三步处理：

1. **在本文件登记现象**：
   在对应条目的「实际结果记录栏」将状态标为 `[x] 失败`，并写明：
   - **机型与系统**：如 `iPhone 15 / iOS 18.1 Safari` 或 `Android 14 Chrome (390×844)`
   - **复现路径**：具体在哪一页、哪个阶段、做了什么手势
   - **观察结果 vs 预期结果**：可附上手机截图文件名或录屏时间点
2. **按问题归属拆成独立新任务（编号取下一个空号，先与 Lead 确认）**：
   每次只针对同一模块的问题建一个新任务（用 `docs/tasks/_template.md` 创建对应任务文件），并在 `docs/TASKS.md` 的「未完成」下登记：
   - **3D 拖拽 / 双击回正 / WebGL 上下文或发热问题** → 新建任务（允许改：`src/components/CubeScene.ts`、`src/components/CubePlayer.tsx` 及对应测试）
   - **练习页触摸按压 / 滑动冲突 / 常亮问题** → 新建任务（允许改：`src/pages/PracticePage.tsx`、`src/lib/practiceKeys.ts`、`src/lib/wakeLock.ts`、`src/styles.css` 及对应测试）
   - **320 矮屏溢出 / iPhone 底部安全区 / 样式遮挡问题** → 新建任务（允许改：`src/styles.css` 及对应布局测试）
   - **离线缓存 / SW 强刷问题** → 新建任务（允许改：`vite.config.ts`、`src/lib/versionCheck.ts` 等及对应测试）
3. **走标准四方流程闭环**：
   Lead 写好新任务规格与验收标准 → 交由 Executor（Codex）在独立分支实现并跑门禁 → Lead 审查 + Auditor 独立复核（确认未放宽 `SET_RULES` 与现有测试）→ 用户批准后合并发布，最后回到本清单复测勾选通过。
