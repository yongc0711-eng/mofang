## 问题与实现

原 selected 属于 CasePage 的 useState，离开路由卸载后丢失，新挂载便使用 primary。

复用现有 uiState 内存 Map，以 `case-selection:<caseId>` 为 key 保存选中的公式字符串：

- 原 setSelected 调用入口保留：点击公式、成功保存公式、删除当前自定义公式都通过同一个写入函数更新内存，并用局部版本 state 触发当前页面重绘。
- 每次渲染都按当前 c.id 读取，不只在 useState 初始化时读取，因此同一组件切换 case 参数也不会带入前一 case 的选择。
- 在把 selected 传给 playing/viewCase 之前，检查字符串仍在当前 c.algs 或 customAlgs 中。失效时同步清掉该 UI 内存项并返回 null，随后原 `selected ?? primary` 回退；无需先显示一帧旧公式再用 effect 更正。
- 失效项清除后，即使相同字符串后来又被添加，也不会自动恢复已删除的选择。
- helper 只清理 uiState，没有 React state 的渲染期更新，也没有修改用户数据。新增自定义公式时的原保存流程不变，下一次渲染按更新后的 customAlgs 校验。
- 完全不写 localStorage、备份或用户主公式。刷新文档会自然重建 uiState Map，按要求允许重置。
- 原删除逻辑 `if (selected === alg) setSelected(null)` 保留；离页期间删除/导入替换导致选择失效，也会在返回的第一次渲染时发现。

## 新增 8 项测试

测试实际 CasePage 与内存 helper，不使用源码正则代替行为：

1. 同 case 用独立 React 服务端渲染根重新挂载，局部 state 已全新创建，播放器参数及图解 view 都恢复选中公式。
2. 不同 case 隔离，即使另一 case 的自定义列表也有同一公式字符串，也不会串选择。
3. 删除自定义选择后回退到当前用户主公式，并确认重新加入该公式不会使失效选择复活。
4. 内置公式从可用列表移除后清理选择。
5. 默认无选择时仍使用用户主公式，无用户主公式时用 algs[0]。
6. 显式清除活动选择立即回退，后续独立挂载保持清除结果。
7. 记忆及读取选择不修改用户数据/备份内容。
8. 当前真实数据中的内置备选公式也可在独立挂载中恢复。

测试中的独立服务端根验证“原组件局部 state 不再存在”的条件；真正浏览器路由卸载/返回另外按下述流程验证。现有 3260 项测试未改、未删除、未放宽、未 skip。
