## 按键、动画与状态

- 主键：R U F / L D B / x y z。
- 更多：r l u / d f b / M E S；复用同一个三行三列网格，不增加行数。“更多”切换后按钮文案为“主键”。
- 后缀：无、撇号、2，以 aria-pressed 显示；只用于下一个成功入队动作，入队即回“无”，所以连点不会重复使用。队列满时不消费后缀。
- 每个按钮 type=button，有 aria-label，最小 44px。动画/队列中禁用撤销；空闲时将最后已完成转动的逆入队播放，撤销动作不重新记入历史。连续撤销可逐步返回起点。
- 复原取消当前 RAF，清空活动动作、队列、历史和后缀，立即绘制 solved；不重新创建场景。复原状态与双击恢复观察视角是不同操作。

纯逻辑 Sandbox 从 solved() 起手，维护 State、待转队列、活动动作及历史。队列上限 16，含当前活动动作；达到上限时按钮禁用，逻辑层也拒绝超额输入。已接收动作按顺序逐一执行。

RAF 每帧调用 tick，以 easeMove 将进度交给 CubeScene.render；场景现有 moveGeometry 负责选择层和旋转角度。90° 160ms，180° 240ms；动画结束才 applyMove。后台大帧间隔按每帧最多 100ms 推进，避免回来跳过整队动作。没有实例化 Timeline 或 CubePlayer，未修改它们；仅复用 timeline 模块现有 easeMove 函数。

x/y/z 同样以引擎 Move 应用，保留旋转后的中心及全部贴纸，不 normalizeRotation，不自动归正。后续 R/U/F 等作用于当前坐标位置，和依次 applyMoves 一致；拖动只改变观察视角。

## 无头 Edge 实测

使用生产构建的 vite preview（127.0.0.1:4178），隔离 profile 的无头 Edge，通过 CDP 设置 320×640、mobile=true、deviceScaleFactor=1。软件 WebGL（SwiftShader）渲染，非 SSR 尺寸推断。

| 项目 | 实测 |
| --- | --- |
| innerWidth / clientWidth / scrollWidth | **320 / 320 / 320** |
| stage | **288×180px**（320 宽专用；220px 会把撤销/复原压到底栏下面） |
| 主键 | 每个约 **90.66–90.67×44px**，九键三行 |
| WebGL canvas / 转动按钮可用 | true / true |
| R2 完成后 | 无后缀 aria-pressed=true，撤销可用，待转 0 / 16 |
| 更多 | r l u d f b M E S，九键 |
| 复原后 | 撤销禁用，scrollWidth/clientWidth 仍 320/320 |
| 1280×800 桌面 | 左右列各 498px |

首轮 320×640 用 220px stage 时撤销/复原被底栏盖住；已加 `@media (max-width: 360px)` 把 stage 缩到 180px，撤销/复原底部约 536px、待转行底部约 563px、底栏顶部 568px（含安全区时以底栏实际高度为准）。

未真机；未在真实移动 GPU、微信/X5、iOS 上验证性能和手势。拖拽/双击沿用原场景，本轮未人工目测手势；真实视角转动后继续面转的交互观感、深浅色及多次路由切换的 GPU 释放还可追加人工验收。没有把纯逻辑状态测试声称为视觉验收。队列满会拒绝新按键，已有 16 个动作不丢；本页状态不持久化，离开后重进从还原态开始。
