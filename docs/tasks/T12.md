# T12 CaseDiagram 图解测试

## 目标与范围

从当前 main（04be791）建立 `codex/t12-diagram-tests`。使用 `react-dom/server` 的 `renderToStaticMarkup` 验证 SVG 贴纸颜色来自 `displayColors`，坐标符合引擎的 x 向右、y 向上、z 向前，并符合黄顶绿前约定。未使用整段快照、手写状态、图片或组件测试框架。

## 改动

- `src/components/CaseDiagram.tsx`：仅导出 TopView、IsoView、LseView，渲染逻辑未改。
- `src/components/CaseDiagram.test.tsx`：新增 12 条测试，解析静态 SVG 的 rect/polygon 属性，按屏幕位置匹配贴纸，避免依赖元素输出顺序。
- `vite.config.ts`：经用户明确追加授权，将测试收集范围从 `.test.ts` 扩展到 `.test.{ts,tsx}`，确保普通 `npm test` 包含新文件。
- `docs/tasks/T12.md`：本报告。

未修改样式、src/data、TASKS.md 或任何现有测试断言。

## 覆盖

- TopView：OLL 1、OLL 27、PLL Ua、PLL T，每个情形分别检查子组件和 CaseDiagram 的 top 分支。顶面 9 格、侧面顶行 12 格，逐一对照引擎 STICKERS 位置和 displayColors（包括 mask）。断言 B 在上边、F 在下边、L/R 在左右，以及格子尺寸。
- IsoView：同上 4 个情形，分别检查子组件和 CaseDiagram 的 iso 分支。对 U/F/R 的 27 个多边形，以独立的正交投影基计算屏幕中心坐标并唯一匹配，逐一断言 fill 和 stroke 与 displayColors 的颜色变量一致。检查没有重复匹配或遗漏贴纸。
- LseView：EO F Arrow（lse-eo-7）、UL/UR（lse-ulur-1）、4c Dots（lse-4c-24），分别检查子组件和 CaseDiagram 的 lse 分支。断言先输出上方顶视图，再输出下方底面；D 面 9 格逐一检查，DF 在上、DB 在下。
- 配色与朝向：只读 styles.css，断言 U 黄、F 绿、R 橙、L 红的现有 CSS 变量。还原参考态也由 displayColors 从空公式推导，断言顶视图 U 中心及 F/L/R 边条的位置；等轴视图 U 中心在 (62,36)，F 在左前 (36.02,81)，R 在右前 (87.98,81)。

测试名按情形展开为：TopView 4 条、IsoView 4 条、LseView 3 条，以及“黄顶绿前：CSS 变量含黄 U、绿 F、橙 R、红 L；还原态中心处于正确的屏幕方位”1 条。

初次配色测试用 CSS raw 导入，Vitest 的默认 CSS stub 返回空字符串，导致 11 条通过、配色测试 1 条失败。这是测试读取方式问题，改为 Node 只读样式文件后通过。项目没有 Node 类型定义，因此测试内为动态加载的文件读取 API 声明最小接口，不引入依赖或更改 tsconfig。
