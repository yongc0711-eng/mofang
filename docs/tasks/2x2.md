## P1：24 贴纸引擎

### 模型

- 8 个角块 × 3 张贴纸 = **24 张**；坐标分量只有 ±1；`state[i]` = 位置 i 上的贴纸编号，还原时 `state[i] === i`。
- 面序沿用 `U R F D L B`，每面 4 张，贴纸 id = `f * 4 + k`（0–23）。
- 位置与法向由 `facePos2(face, r, c)` / `faceNormal[face]` 生成（r、c ∈ {0,1}），禁止手写置换表；转动由几何旋转生成，做法与 `src/lib/cube.ts` 的 `ROT` 一致。
- 不提供 `normalizeRotation`：2×2 没有中心，整体转体无法靠中心对齐消掉。

### 接口

```ts
// src/lib/cube2.ts
import type { Face, Move, Vec } from './cube';

export interface Sticker2 { id: number; face: Face; p: Vec; n: Vec }
export const STICKERS2: Sticker2[];            // 24，id 0..23
export function stickerAt2(p: Vec, n: Vec): number;
export type State2 = number[];
export const solved2: () => State2;
export function applyMove2(state: State2, move: Move): State2;
export function applyMoves2(state: State2, moves: Move[]): State2;
export function moveGeometry2(move: Move): { axis: 0 | 1 | 2; layers: number[]; angle: number };
export const BASES2: string[];                 // 'R L U D F B x y z'
```

- 允许的转动只有 `R L U D F B` 与整体 `x y z`；`M E S`、宽层（`r u f l d b`）在 2×2 上没有意义，`BASES2` 不含它们，遇到就抛 `Error`。
- 面转只动 `p[axis] === ±1` 的那一层；整体转体动两层 `[-1, 1]`。
- `moveGeometry2` 的轴、层、角度约定与三阶 `moveGeometry` 完全一致（角度正负也一样），这样时间线可以复用。

### 验收（`src/lib/cube2.test.ts`）

- 24 张贴纸 id 唯一、每面 4 张、每个角位置恰好 3 张、法向与位置垂直。
- 每个面转 4 次回到还原；`x`、`y`、`z` 各 4 次回到还原。
- 任意转动的逆：`applyMoves2(applyMoves2(s, m), invertMoves2(m))` 回到 `s`（随机 40 步序列跑一批）。
- 已知序列 `R U R' U'` 循环 6 次回到还原；`R U` 与 `U R` 结果不同。
- 转动不合法：`M`、`r`、`E` 抛错。
- 角块不变量：任意序列后，角朝向和 ≡ 0 (mod 3)，置换为偶（用角块三元组算，不依赖 3×3 的贴纸编号）。

**只新增 `src/lib/cube2.ts` 与 `src/lib/cube2.test.ts`，不改既有文件。** 门禁：`npm test` 现有 6198/60 全过且总数只增；`npm run check:data` 1097/9 不变；`npm run build` 通过。

### 图解 `src/components/CaseDiagram2.tsx`

- 与 `CaseDiagram.tsx` 同风格：`memo` 纯组件、viewBox 单位（cell 20、gap 2、strip 7）、`fill(f)` 复用 `var(--cube-*)`、`null` 走 `var(--cube-mask)`、`aria-hidden`。
- 格子一律由坐标算出（`stickerAt2(p, n)`，p 分量 ±1），不手写「第几格是哪个 id」的映射表。
- `TopView2`（12 格，与 3×3 `TopView` 同方位，F 在下、R 在右）：
  - 顶面 2×2：`stickerAt2([x, 1, z], [0, 1, 0])`，x、z ∈ {−1, 1}；
  - 上条 B：`([x, 1, −1], [0, 0, −1])`；下条 F：`([x, 1, 1], [0, 0, 1])`；
  - 左条 L：`([−1, 1, z], [−1, 0, 0])`；右条 R：`([1, 1, z], [1, 0, 0])`。
- `BottomView2`（12 格）：**F 在上、R 在右**，等于把魔方绕 x 轴往前翻 90° 再看原来的底面（不是镜像）：
  - 底面 2×2：`([x, −1, z], [0, −1, 0])`，z = 1 画在上；
  - 上条 F：`([x, −1, 1], [0, 0, 1])`；下条 B：`([x, −1, −1], [0, 0, −1])`；
  - 左条 L：`([−1, −1, z], [−1, 0, 0])`；右条 R：`([1, −1, z], [1, 0, 0])`。
- `CaseDiagram2({ colors, view })`：`view` 取 `'top2' | 'both2'`；`'both2'` 是两个 SVG 并排（`display: flex; gap`，宽度随容器），两个 SVG 各给 `aria-label`「顶视图」「底视图」。
- 测试 `CaseDiagram2.test.tsx`（`@testing-library/react`）：
  - 格数：`TopView2` 12 个 rect、`BottomView2` 12 个、`both2` 24 个；
  - 映射：`colors[i]` 用确定性数组（第 i 张 = `FACES[i % 6]`），断言某几格拿到的 id 等于按 `STICKERS2` 的 p/n 过滤出来的 id（不从 `stickerAt2` 反推，避免自证）；
  - 方位（用 `applyMoves2(solved2(), parseAlg('R'))` 派生状态，不手写状态）：`R` 只动 x = +1 的贴纸，所以顶视图右列（U 的 x=1 两格 + F/B 的 x=1 条）变化、左列与 L 条不变；底视图同样右列变化、左列不变——这同时锁住「F 在上、R 在右」的口径。

### 规则（`src/lib/cases2.ts`）

- 独立的 `SET_RULES_2` 与校验函数，**不动** `src/lib/cases.ts` 的 `SET_RULES`、`caseState`、`algSolvesCase`。
- `caseState2(c)` = `applyMoves2(solved2(), invertMoves2(parseAlg(c.algs[0])))`。
- 不变量（用状态本身判定，不手写贴纸）：
  - **CLL**：底层四角全部归位且定向（4 个 `D` 色贴纸都在 `D` 面，且底层侧色与所在面一致）。

- 解出判定：`applyMoves2(caseState2(c), parseAlg(alg))` 必须与 `solved2()` **逐元素相等**（残留整体转体不算解出）。
- 去重：2×2 没有中心，整体转体是同一个情形；指纹取 24 个朝向下的最小表示，组内不得重复。与来源分组冲突时先报告。
