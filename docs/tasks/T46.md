## 先定位：动画与滚动分开

在 390 × 844 的真实浏览器页面 `/case/pll-t`，按“输入框展开→收起→再点输入框”检查基线：

1. 收起后 `.alg-keyboard` 节点数量为 **0**，不是一直保留的显示/隐藏节点。
2. 再次挂载后尽早读取到 opacity **0.735933**、transform Y **1.84847px**。这证明本机基线的 CSS 动画确实再次播放，并非可以断定“只有首次创建动画”。延迟读取会看到 opacity=1 / transform=none，所以不能用动画结束后的快照判断没有重播。
3. 基线动画仅 7px / 170ms。第二次采样时面板已经处于屏内，最近边缘对齐没有必要再移动视口；之前一次面板完成后位置约 top=510.78 / bottom=736.47px。`nearest` 没有滚动距离是合理行为，不能人为增加位移来假装动画修复。

结论：本机证据支持“很轻的面板动画 + 第二次通常不需要滚动”造成不明显；没有证据把问题归因于 CSS 节点复用。本次显式建立每次展开的独立动画 key，并增强面板动效；**不修改滚动逻辑或强制滚动距离**。

## 实现

- 用 keyboardOpenRef 记录输入事件中的当前开关状态，保留原 setKeyboardOpen 的布尔/函数调用形式。
- 只有 false→true 时将 keyboardEntry 加一；wrap 使用 `key={keyboardEntry}`。连续 true、关闭、草稿输入、提示等状态更新都不会增加 key。
- ref 在事件里更新，递增的 React updater 是纯函数；不在 updater 内嵌套其他 setState。连续快速切换仍按当前状态计算。
- 原 `{keyboardOpen && (...)}` 保留，关闭立即卸载；没有退场等待或延迟更新开关状态。
- 面板改为 **14px / 200ms ease-out** 的 opacity + transform 入场，属于任务允许的范围。没有 height/margin/padding 动画，也不禁用按钮或屏蔽 pointer events。
- 原 rAF + scrollIntoView effect 完全不动：每次开都调用 nearest，正常 smooth、减少动效 auto；没有 scrollBy/scrollTo 或固定偏移。
- 原减少动效 `.alg-keyboard { animation: none; }` 保留。

## 测试

原 3256 项测试全部保留。T44 的数值断言依本任务明确授权的范围从精确 170ms/7px 更新为精确 200ms/14px；没有扩大匹配范围、删除条件或放宽 T42 断言。

新增 4 项，执行页面源码中的实际开关控制器，而非另写一套模拟业务规则：

- 连续开→关→开：key 1→1→2，第二次挂载明确绑定新 key；两次 open 的原滚动 effect 都触发 smooth，关闭不触发。
- 已展开时重复 focus/open 不增加 key；重复 close 也不增加。
- 快速函数切换六次，只有三次真实开，key 精确为 3；再次打开为 4。
- 第二次展开在 reduced-motion 下调用 auto，且没有人为滚动 offset；新动画参数有精确断言。

原 CSS 动画只含绘制属性、reduced-motion 禁用、立即条件卸载、scroll-margin 等断言继续通过。
