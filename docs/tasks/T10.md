# T10 强制保存的公式会影响练习打乱

## 背景

`CasePage` 里“仍然保存”的公式会被 `addCustomAlg` 设成 `primaryAlg`。练习页原来按主公式的逆生成打乱，所以主公式解决不了该情形时，打乱和图解对不上。导入的备份也可能带来这种主公式。

## 目标

- 强制保存的公式不能成为主公式
- 练习打乱的起始状态由情形定义（`algs[0]`）推导，和用户选的主公式无关
- 读取主公式时，如果它解决不了该情形，回退到 `algs[0]`

## 允许改

- `src/pages/CasePage.tsx`、`src/pages/PracticePage.tsx`
- `src/store/userStore.ts`、`src/lib/practice.ts`、`src/lib/practice.test.ts`
- 新增 `src/store/userStore.test.ts`

## 验收

- `npm test`（461 项）、`npm run check:data`（367 项）、`npm run build` 全过
- 新增测试覆盖：强制保存不改主公式；打乱与主公式无关；解决不了的主公式读取时回退

## 非目标

- 不改 `SET_RULES`、`src/data`、公式 `id`
- 不禁止用户保存这类公式，不改备份格式

## 进展

- 2026-11-07：`addCustomAlg(id, alg, setPrimary = true)`，`CasePage` 保存时传 `solves`，所以只有解决得了情形的公式才会自动成为主公式。
- `scrambleFor(c, rand?)` 不再接收公式，用 `algs[0]` 的逆；OLL/PLL/CMLL 仍加随机 AUF，F2L/LSE 不加。
- `primaryAlgOf`：内置备选公式照旧可选；自定义公式要 `algSolvesCase` 通过才算主公式，结果按“情形 id + 公式”缓存，因为列表页每次渲染都会调用。
- `CasePage`：解决不了该情形的自定义公式不再显示“设为主公式”，改显示“解决不了此情形”。这是为了让界面和上面的规则一致。
- 现有测试 `practice.test.ts` 里三处 `scrambleFor` 的调用去掉了公式参数，断言一字没改。签名变了，调用必须跟着改。
