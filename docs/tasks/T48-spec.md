# T48 方案卡：详情页 3D 播放器首屏占比过大

状态：方案卡已审，用户定了“390×844 上要露出 ≥100px”，已按方案 B 实现，见文末“实现记录”。基线 main=`c036d1d`。

## 1. 复现与尺寸

用开发服务器，在内置浏览器里把视口设成手机尺寸，打开 OLL 27（有“识别”）和 PLL Ga（公式较长），用 `getBoundingClientRect` 量（文档坐标，单位 px；底栏是悬浮胶囊）。截图看过（390×844），没有存进仓库，数据都在下表。

### 390×844，OLL 27

| 区块 | 顶部 | 高度 | 底部 |
| --- | --- | --- | --- |
| 返回 + `.case-head`（2D 图解、标题、收藏、学习状态） | 62 | 193 | 255 |
| `.player` 整块 | 269 | **516** | 785 |
| 其中 `.player-stage`（3D 画面） | 270 | 340（= `min(46vh, 340px)`，被 340 封顶） | 610 |
| 其中 `.move-track` / 进度条 / 控制行 / 速度行 | 610 / 646 / 674 / 740 | 36 / 28 / 58 / 32 | 772 |
| `.focus-chip`（只看相关的块） | **793** | 34 | 827 |
| `.case-side` 开头（“识别”） | **841** | — | — |
| 公式列表（`.alg-list`） | 960 | 202 | 1163 |
| 悬浮底栏 `.nav` | 772 | 60 | 832 |
| 文档总高 | | | 1414 |

读数：

- 视口 844，`.case-side` 从 **841** 才开始，几乎正好在视口底边；而底栏占 772–832，所以首屏里**一点“识别 / 公式 / 添加公式”的正文也看不到**。
- `.focus-chip` 在 793–827，**整个被悬浮底栏盖住**。这是现有的一个附带问题：首屏上“只看相关的块”按钮点不到，要滚动才出现。
- 播放器本身 516px = 画面 340 + 步骤 36 + 进度 28 + 控制 58 + 速度 32 + 内边距，画面只占 66%，其余 34% 是控件。
- 学习状态（T45）和 `.case-head` 一起占到 255，也在吃首屏，但它是用户刚要求的，本方案不动。

### 320×640，PLL Ga

- `.case-head` 56–249，`.player` 263 起高 498（画面 294 = 46vh，步骤区换行成 63px），`.case-side` 从 **816** 开始，视口只有 640，**整段内容完全在首屏之外**；`.focus-chip` 在 768，同样在底栏下面（568–628）也在视口之外。
- 没有横向滚动。

### 宽屏

≥800px 两栏，`.player` 是 `position: sticky`，画面 360px，右栏内容和播放器同屏可见，**没有这个问题**。本方案只针对手机（`max-width: 799px`）。

### 根因

不是某行写错，是三件事叠加：播放器高度只按 vh/固定值取，不知道上面有多高（`.case-head` 因 T45 变高了）、下面有多少内容；控件区占了三分之一；首屏下沿没有任何“下面还有东西”的提示。

## 2. 目标

1. 进入页面后：3D 仍然是可用的（能拖、能看清、能播放）。
2. 用户**不用猜**就知道下面还有识别、公式列表、添加公式。
3. 不是把魔方缩到看不清：画面有下限。

可量化的验收口径见 §5。注意：**不把“缩到多少 px”当成唯一答案**，因为视口高度、`.case-head` 高度、公式步骤行数都会变。

## 3. 方案

### 方案 A：只加“提示”，布局不动（最低成本）

在播放器下方、首屏下沿处放一个明显的提示（例如“↓ 识别与公式”小条，点击平滑滚到 `.case-side`），并给 `.case-side` 一个锚点。

- 优点：几乎不碰布局；3D 完全不变；风险最小。
- 缺点：首屏仍然是“一个大魔方 + 控件”，提示只是提示；`.focus-chip` 被底栏遮住的问题没解决（提示条本身也会和底栏抢位置）。
- 影响：`CasePage.tsx`、`styles.css`。

### 方案 B：按预算收紧播放器，并保证露出一截内容 + 提示（推荐）

三件事一起做，只在手机宽度生效：

1. **画面高度按预算算，不写死**：把可用高度分给各块——`视口高度 − 底栏占位 − 上方已占高度 − “露出预算”`，再夹在下限和上限之间（例如用 `clamp(下限, 随 dvh 变化, 上限)`；具体数字在实现里按 §5 的验收在 320×640、360×740、390×844、414×896、横屏 844×390 上调）。下限保证魔方看得清、能拖；`dvh` 为不支持的浏览器留 `vh` 回退。
2. **压缩控件区**：速度选项并进控制行（或收成一个紧凑分段）、步骤行保持换行但字号/行距收紧，目标是把非画面部分从约 176px 压到约 110px 以内；触控目标仍 ≥ 32px（`.ctl` 44px 不变，速度按钮保持 `min-height: 32px`）。
3. **把“只看相关的块”从播放器下面挪到画面角落**（作为画面上的小浮层按钮，位置在 `.player` 内部，不在 `.player-stage` 的拖拽区里），这样首屏上不会再被底栏盖住，也省下约 42px。
4. **露出预算 + 提示**：在能做到的视口里（例如 390×844），保证 `.case-side` 的开头至少露出一截（见 §5）；做不到的小屏（例如 320×640），保留方案 A 的“↓ 识别与公式”提示条，保证任何视口下首屏都有“下面还有内容”的明确信号。

- 优点：既保留 3D 的可用性，又有稳定的露出；解决 chip 被盖住；宽屏不变。
- 缺点：改的地方多一点（布局 + `CubePlayer` 的标记结构），要在多个尺寸上手测；控件压缩后点击区域更紧。
- 影响：`CasePage.tsx`、`CubePlayer.tsx`（只改标记结构与类名，不动播放逻辑）、`styles.css`、测试。

### 方案 C：把内容做成底部抽屉，3D 固定在上面

3D 占上半屏固定，识别/公式在底部可上拉的抽屉里，首屏露出抽屉的头。

- 优点：首屏信息最明确。
- 缺点：最大的改动。抽屉是内层滚动容器或自定义手势，会和 `.player-stage` 的 `touch-action: none`、T43 的页面弹性（文档级 `touch`/`wheel` 接管）、T42 的键盘 `scrollIntoView`、固定底栏、PWA 的 safe-area 全部冲突，要重做滚动模型；回归面很大。
- 结论：**不推荐**，除非 B 在真机上仍然不够。

### 取舍小结

| | A 只加提示 | B 预算收紧 + 提示（推荐） | C 抽屉 |
| --- | --- | --- | --- |
| 解决“不知道下面有内容” | 部分（只有提示） | 是（露出 + 提示） | 是 |
| 保留可用 3D | 是（不动） | 是（有下限） | 是 |
| 解决 chip 被底栏盖住 | 否 | 是 | 视实现 |
| 改动面 | 小 | 中 | 大 |
| 手势 / sticky / PWA 风险 | 低 | 中 | 高 |

## 4. 推荐

**方案 B，且把 A 的提示条作为兜底一起做**（小屏做不到露出时仍有明确信号）。先做 B 的“控件压缩 + chip 挪位”（确定性收益最大、风险最小），再做“画面高度按预算”，每一步都能单独验收、单独回退。

## 5. 验收标准（手机，浅色 + 深色）

在 320×640、360×740、390×844、414×896、横屏 844×390 上：

1. **3D 可用：** 画面高度 ≥ 下限（建议 ≥ 200px，且不小于画面宽度的 0.6），能拖动旋转；播放 / 暂停 / 上一步 / 下一步 / 进度条 / 速度都能点，触控目标 ≥ 32px。
2. **有明确信号：** 首屏（不滚动）里一定能看到下面还有内容——390×844 上 `.case-side` 的开头（“识别”或“公式”标题 + 至少一行）露出 ≥ 100px 且不被底栏遮住；做不到的尺寸（例如 320×640）至少出现“↓ 识别与公式”提示条，点击能滚到 `.case-side`。
3. **“只看相关的块”按钮在首屏可见、可点，不被底栏遮住。**
4. 不横向滚动；固定底栏和 safe-area 正常（底部 `env(safe-area-inset-bottom)`）；`prefers-reduced-motion` 下提示条的滚动用 `auto`。
5. 宽屏（≥800px）布局、sticky、画面 360px **完全不变**。
6. 播放 / 暂停 / 进度 / 速度 / 掩码 / 拖拽行为不变；`Timeline`、`CubeScene` 的播放逻辑零改动；T42 键盘、T45 学习状态、T46/T47 入场动画、2D 图解不变。

## 7. 非目标

- 不改 `Timeline` / `CubeScene` 的播放逻辑，不改公式数据。
- 不改 2D 图解、T42 键盘、T45 学习状态（它占的高度算已知背景，不在这里压缩）、T46/T47 入场动画。
- 不引入新依赖；不做抽屉；不改宽屏两栏和 sticky。
- 不把魔方缩到看不清；不以某个固定 px 作为唯一标准。

## 8. 风险

- **3D 手势：** `.player-stage` 是 `touch-action: none`，画面变矮后拖拽区域变小；chip 浮层如果放进拖拽区会抢手势，所以放在 `.player` 里、`.player-stage` 之外（或明确阻止事件冒泡），测试要覆盖。
- **sticky（宽屏）：** 只在手机媒体查询里改，宽屏规则一行不动，用测试锁住。
- **PWA / 移动端地址栏：** 用 `dvh`，不支持的浏览器回退 `vh`；独立模式下视口高度与浏览器标签页不同，要两种都量；底栏用 `--nav-gap` / `safe-area` 算占位，不要写死 60。
- **性能：** 画面尺寸变化会触发 `CubeScene` 的 `ResizeObserver` 重设渲染尺寸；只在进入页面和旋转屏幕时变，不要在滚动中动态改高度（否则每次滚动重绘）。
- **旧布局：** 学习状态（T45）、键盘（T42）的 `scrollIntoView`、T43 页面弹性都依赖文档流；提示条和锚点滚动不要用 `overflow` 容器，只用文档级 `scrollIntoView`。
- **提示条占位：** 它自己也会占首屏和被底栏遮住，位置要按底栏占位算，而不是 `bottom: 0`。
- **回退：** 方案 B 按三步拆开提交（控件压缩、chip 挪位、画面预算），任何一步都能单独 revert；提示条是独立组件，可单独去掉。
