# T56 微信内置浏览器：检查更新与强制刷新

日期：2026-11-08（Asia/Shanghai）。独立 worktree `D:\allwork\mofang-codex`，分支 `codex/t56-version-update`，基线 `main@ecc5c3a`。

## 问题与目标

PWA 的旧页面可以长期保持旧 JS；SW 预缓存和微信容器内的缓存又使普通重新访问不一定进入新包。本任务增加独立的远端版本发现和用户明确点击后的换包操作，不让练习中出现静默重载。

## 构建与版本协议

- Vite 配置每次执行生成 `ISO UTC 时间 + crypto.randomUUID()`，不依赖固定版本、git 工作树状态或新依赖。
- 同一次构建用 define 注入 `__BUILD_ID__`，并在 generateBundle 输出 `dist/version.json`，格式为 `{ "version": "<build id>" }`。`src/build.d.ts` 提供全局类型，前端和元数据使用同一 ID。
- Workbox 显式 globIgnores 排除 version.json，原 globPatterns 本来也不含 json；同时将其排除出导航 HTML fallback。没有加版本文件的 runtime cache。
- 本地开发中间件也返回当前配置的版本，Cache-Control=no-store。生产依赖真正的构建产物。
- 已检查 CI：deploy.yml 执行 npm run build，随后上传整个 dist，因此同一个 Vite 构建钩子覆盖本地及 CI，无需改 workflow。

两次真实连续构建的产物：

```json
{"version":"2026-11-07T17:16:12.937Z-89b4d100-df9e-4508-884b-a6f61307efb1"}
```

```json
{"version":"2026-11-07T17:17:15.638Z-b9f3bd7a-ac17-40b4-838e-a973c48da0dd"}
```

ID 内时间是 UTC（本地验收日期为 11 月 8 日）。两次均验证：文件存在、JSON 可解析、ID 不同、对应主 JS 含相同 ID。解析生成 SW 的 precache URL 列表，均为 9 项且**没有 version.json**；不是用全文件“不含 version.json”误判，因为 SW 的 denylist 正常会含该字符串。第二份 JSON 是本次最终保留的 dist/version.json。

## 更新模块与交互

`src/lib/version.ts`：

- checkVersion：请求 `./version.json?ts=<Date.now()>`，cache=no-store；检查 HTTP、JSON 和非空 version 字符串，8 秒 abort 定时器，错误交给调用方。
- isNewVersion：比较不透明 build ID 是否不同，不把 UUID 当语义版本号，也不声称能判定远端是升级还是回滚。
- createVersionChecker：按当前文档记录上次**尝试**时间，自动检查至少间隔 30 分钟，失败也节流；进行中的请求复用。手动按钮可绕过间隔，但仍复用在途请求。
- watchVersionChecks：初次可见、visibilitychange=visible、window focus 时检查；隐藏时跳过，卸载移除监听。没有轮询 interval，持续前台且没有新事件时不会自行每 30 分钟发请求。
- 自动失败返回 failed，不弹窗、不输出打断操作的错误，不修改练习/计时/滚动或调用刷新。
- forceReload：依次获取本 origin 所有 SW 注册并逐一注销，再枚举并删除本 origin 所有 CacheStorage 缓存，全部完成后 location.replace。URL 保留 origin/path、其他 query 和 hash，只新增/覆盖 v 时间戳。
- 单个清理失败仍尝试其余项与下一阶段；有失败时不声称清理成功、不继续替换页面，界面提示重试/系统浏览器。没有 SW/CacheStorage API 时跳过不可用功能，仍可执行带新参数的导航。
- 不访问或清理 localStorage、IndexedDB、cookie；进度、偏好和原练习会话不作为缓存删除对象。

App 内新增独立 UpdateNotice：共享内存订阅、role=status/aria-live=polite，不获取焦点，不触发程序滚动。检测新版后出现“有新版本，点此刷新”，**只有点击才调用 forceReload**。提示条在 main 内正常文档流中，不用 fixed/sticky，不叠在键盘或播放器上。出现时会占用正常内容高度；没有改 T53 的位置恢复算法。

MePage 增加“检查更新”（检查中禁用）和独立“强制刷新”。分别提示已最新、新版、失败；强制刷新使用内联确认/取消，可在版本检查失败或没有新版本时作为兜底。刷新中禁用对应操作；清理失败可重试。显示当前 build ID 便于对照，长字符串允许换行。

## 注册与导航边界

- **保留 registerType: autoUpdate**，没有必要切换注册模式。没有引入 virtual:pwa-register 或 controllerchange 重载监听。
- 实际生成的 registerSW.js 仍只在 load 注册 SW；本功能的版本检查模块没有任何自动 reload 路径。生产 A/B 测试也确认，发现 B 后页面仍是 A，直到点击刷新。
- 对 ecc5c3a 做函数文本比较，navigationUnchanged=true、routesUnchanged=true。
- main.tsx、T49–T55 的导航/滚动模块、CasePage、练习页/算法、公式数据、SET_RULES、userStore、devicePrefs、TASKS.md、依赖文件均未改。
- 明确点击刷新属于一次真正导航，会按原 T21 规则恢复/暂停会话；不保持播放器时间、页面内存选择或底色多选等临时 UI 状态。这些不是新的静默状态变更。

## 微信限制与手动兜底

- **首次上线前已打开的老 JS 没有本功能，无法被新代码隔空升级。** 首次进入包含 T56 的包仍可能需要关闭旧页面、重新打开，或从系统浏览器进入；此后常驻的 T56 页面才有后台发现能力。
- SW 注销不是强杀当前所有客户端；其在途工作可以继续，其他同源窗口也可能重新注册。CacheStorage 也只是一类 Web 缓存。这里不保证能删除微信容器/HTTP/代理缓存或绕开微信版本差异。参考 [SW unregister 的官方说明](https://developer.mozilla.org/en-US/docs/Web/API/ServiceWorkerRegistration/unregister)、[CacheStorage.delete 的官方说明](https://developer.mozilla.org/en-US/docs/Web/API/CacheStorage/delete)。
- 本轮未连接微信/X5 真机；后台事件/定时器被挂起、平台 API 拒绝访问等仍需微信实测。没有 API 时仍尝试带 v 导航；API 有但清理拒绝时会提示失败，不假称换包成功。
- 自动检查失败时继续当前使用；需要更新时联网进入“我的”点“检查更新”，或点“强制刷新→确认刷新”。清空离线缓存后需要重新下载资源，离线时不要主动执行强制刷新。
- 若仍旧包：关闭旧窗口，使用系统浏览器打开同一路径和 hash（可带新的 v 参数）；必要时先导出备份，再按微信容器提供的方式清理网页缓存。系统/微信级清理可能影响本地数据，区别于本按钮只清 SW/CacheStorage 的范围。
- 按要求清理的是**整个同源**所有 SW 注册和 CacheStorage，包括共享 origin 的其他路径应用；不是仅清某一个 SW scope。不清用户备份数据，但离线资源需要重建。
