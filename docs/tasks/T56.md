## 问题与版本协议

PWA 常驻页面可能一直运行旧 JS。提供版本检查及用户主动刷新，不静默重载，不打断练习。

- Vite 每次构建生成 `ISO UTC 时间 + crypto.randomUUID()`，同一 ID 注入 `__BUILD_ID__` 并输出 `dist/version.json`。本地构建和 deploy.yml 的 npm run build 共用该钩子。
- version.json 不进预缓存，不走导航 HTML fallback；checkVersion 请求 `./version.json?ts=<时间戳>`，cache=no-store，8 秒超时。比较的是不透明 ID 差异，也能发现回滚，不判断版本大小。
- 自动检查只在首次可见、focus、visibilitychange=visible 时触发，尝试之间至少间隔 30 分钟，失败也节流；手动检查可绕过间隔，仍复用在途请求。**没有 30 分钟定时器**：持续前台且没有切换事件时发现不了新版，由“我的→检查更新”兜底。本次没有加定时器。
- 每次部署构建（包括仅改文档的 push）都会换 ID，所有仍在旧包的用户都会看到新版提示。这一策略未改变。
- 检查失败静默；“我的”页手动检查显示检查中、已最新、新版或失败。UpdateNotice 只通知，点击才刷新。保留 registerType: autoUpdate，没有加 controllerchange 自动重载。

## 本次退回修改

原实现的问题：清理任一阶段失败即拒绝导航，且清理整个 origin，可能影响同域其他项目。

### 清理失败仍导航，诚实报告结果

`forceReload` 分阶段尝试获取 SW 注册、注销、枚举缓存、删除缓存；同一阶段各项用 allSettled，某项拒绝不跳过其他项。API 属性读取本身抛错也在保护范围内。缺少 API 或出现拒绝时 `cleaned=false`；最后仍调用 location.replace，保留 path、其他 query 和 hash，增加/覆盖 v 时间戳。只有导航本身失败仍向调用方抛错。

返回 `{ cleaned, warningStored }`，调用方能区分清理不完整。导航前尝试在 sessionStorage 写唯一一次性标记：`mofang.reload-incomplete:<本应用完整 scope>`，值为 `1`。“我的”页读取后显示：

> 可能仍是旧版，请关闭后用系统浏览器重新打开。

读取与消费分开，避免 React StrictMode 双次初始化提前吃掉提示；挂载后的 effect 只删除本应用标记，不清空 sessionStorage。成功清理则移除旧的本应用标记。sessionStorage 不可用/写入拒绝时，返回 warningStored=false，仍导航；此时不能保证导航后能显示警告。若重新载入的是真正的旧代码，也不能保证它认识此标记。

**残留 SW 可能把带 v 的导航回退到旧 index.html；本功能不承诺一定换包。** 注销也不等于强杀现有客户端。没有访问或清理 localStorage、IndexedDB、cookie，不删除用户进度、公式、偏好和会话数据。

### 只清理本应用的离线缓存

scope 精确取 `new URL('./', location.href).href`。只注销 registration.scope 完全相同的注册。只删除名称以这个完整 scope 结尾的缓存；其他 scope 的注册和缓存原样保留，包括同域兄弟应用、父路径和子路径应用。

没有采用单纯 includes：子应用的缓存名也包含父应用 scope，误用 includes 会删掉子应用缓存。完整后缀匹配既满足缓存名含本应用 scope，又排除子应用。未知命名且没有完整 scope 后缀的缓存保守保留。确认文案同步为“将尝试清理本应用的离线缓存并重新加载”。

### 生成产物核对缓存名（不是浏览器实测）

检查实际生成的 `dist/sw.js`：调用 Workbox precacheAndRoute，未指定自定义缓存名。它导入的 `dist/workbox-9c191d2f.js`（Workbox 7.4.0）缓存名工厂以 `registration.scope` 作 suffix，用连字符拼接 prefix、precache-v2、suffix。

## 已知限制、手动兜底与待验证

1. 自动检查没有周期定时，持续前台依赖手动按钮；文档部署也提示新版，详见版本协议。
2. **提示条影响 T48 的露出保证，尚未修复。** UpdateNotice 在文档流中，显示时把内容下推。复审者在 320×640 打开 OLL 27 测得播放器控制条底部 632，底栏顶部 568；T48 的 `--player-above: 270px` 未计入通知条，原 ≥100px 露出保证在通知显示期间会打折。不能据“提示非 fixed”声称不会遮住控制条。本次不改布局、导航、滚动，保留此问题供单独任务。
3. 未验证真实浏览器 SW 注册后的行为，未连接真机微信/X5。API 拒绝已有替身测试覆盖，但容器实际导航、残留控制器及 HTTP/私有缓存仍需实测。
4. 页面长期运行的是尚无本功能的旧 JS 时，无法被新代码隔空升级。清理失败、残留 SW、系统私有缓存都可能使带 v 导航仍为旧版；sessionStorage 被禁时一次性提醒也可能无法跨导航保存。
5. 手动操作：联网后进入“我的→检查更新”；需要时“强制刷新→确认刷新”。若仍为旧版，关闭旧页面后用系统浏览器重新打开站点。网页不能保证能直接唤起微信外的系统浏览器。删除本应用离线缓存后需要联网重建资源。
6. 如需微信系统级清缓存，先导出备份；系统级清理可能影响用户数据，与本按钮只处理本应用 SW/CacheStorage 的范围不同。
