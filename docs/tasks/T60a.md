## 数据、迁移与旋转

原 BOTTOM_ROTATION / displayFace / topColor / frontColor 等抽到 lib/colorScheme.ts，从 devicePrefs 原路径再导出，保持旧 API 与 CFOP 六色逐贴纸结果不变，也避免纯映射依赖存储模块的循环。

Roux 用还原参考副本先应用 BOTTOM_ROTATION，再枚举 y 的四个方向；由 D 中心底色、L/R 对色对及 leftColor 选唯一候选。完整六面 palette 来自引擎整体转体，不手写桥块颜色，不移动 caseState。非法底/桥对、left 不属于 pair 直接抛错；生成候选只可能是合法旋转，不做镜像/normalizeRotation。六色齐全与正手性有独立几何测试。

默认左色：green-blue 对取 blue，red-orange 取 red，white-yellow 取 white。交换通过修改为另一侧色选择唯一 y2 方向，完整左右/前后互换、上下不变。底色改变时合法桥对及显式方向保留；不合法则采用该底原默认配色的桥对及文档规定的默认左色。

迁移时没有新字段则旧合法 bottom 初始化两方法；Roux pair / left 取旧配色的左右身份，六种旧底下 54 贴纸均不翻转。非法/缺失旧底回白 + 红橙 + 红左。存储里新增字段逐方法清洗并去掉无关字段；非法桥对/左色回合法默认。运行时构造非法配色报错与读取脏存储清洗是两个边界。更新深层对象合并后统一规范化，不丢另一方法；修改旧 bottom 或全局 finish 不重置已保存的新方向。
