## 问题

旧 window keydown 直接 advance，没有 keyup。触屏则非 running 时按下只准备、松手才 advance，导致空格长按在尚未松开时已经开始计时。

## 实现

- `spaceDown` / `spaceUp` 是实际被页面调用的纯决策函数；不包含计时或持久化。
- ready / paused / done：非 repeat keydown 记录当前 phase、armed=true，显示现有 pressing 反馈；keyup 仅在 phase 未变、题目可用、页面可见且没有按钮/链接或 pointer 占用时 advance。
- running：keydown 立即 advance 停表，记录 armed=false；后续 keyup 只释放输入占用，不能进入下一题。
- repeat 不重新 arm，也不 advance；已接管的空格 repeat 仍 preventDefault，以免长按滚动页面。焦点在 a/button 时不 preventDefault，不夺取其原生操作。
- phase 变化清除 pressing，并撤销已准备的动作。保留“物理键/指针尚未松开”的占用直到 keyup/pointerup，避免 running 停表后还按住空格时，另一输入马上启动 done 的下一题。这一占用不显示 pressing，也不会存入会话。
- pointerdown 和空格 keydown 都检查另一方占用。running 的 pointerdown 同样保留未 armed 的占用，后续 pointerup 只清理；原 T24 按下停表/松手忽略不变。
- pointer 的 setPointerCapture、非主指针/鼠标键过滤、取消、丢失捕获均保留。Enter 正常单次操作仍保留，已有 hold 时不允许 Enter 绕过互斥。
- `watchPressCancellation` 统一实际 blur、pagehide、visibilitychange=hidden 的监听接线；清掉两类 hold 和 pressing，并释放捕获。卸载移除监听及输入占用。这里只清输入，绝不暂停/继续或重置计时。

## 新增测试（18 项）

不是源码正则测试，直接调用真实决策函数、原计时函数和事件监听：

- ready / paused / done 各验证 down 不 advance、up 才 advance、重复 up 不触发。
- ready 用 1000→2000 ms 的时钟验证按住一秒 elapsed 仍为 0，释放时才建立 runningSince。
- paused 按住保留累计 500 ms，释放后才续计。
- running down 立刻停表，phase 变 done 后 up 不 advance。
- 四个 phase 各连续 20 次 repeat，均不触发或重新准备。
- a/button 焦点不接管；移到按钮后的释放取消先前 arm。
- pointer 占用时空格不能开始或停表；phase 变化撤销 arm，即使 phase 再回原值也不能误触发。
- hidden / 无题准备中不能 arm，取消后的无主 keyup 不触发。
- 用真实 EventTarget 分别派发 blur、pagehide、visibilitychange，验证页面使用的监听器清 hold，随后 keyup 不能启动；visible 的 visibilitychange 不取消，卸载后监听已移除。

## 浏览器键盘操作验证

环境：本机桌面内置浏览器，390 × 844 视口；使用浏览器键盘/指针输入接口操作页面并在按住期间读取 DOM 和截图，不向页面注入事件或修改状态。

| 场景 | 实际观察 |
| --- | --- |
| ready 空格按住约 1.2 秒 | 按住时 phase=ready、pressing=true、elapsed=0.00，橙色按下反馈及“松开开始”可见；松手后 running，刚释放的画面约 0.17–0.18 秒 |
| running 空格按下 | 当次立刻变 done，读到 19.09 秒；继续按住及松手后仍为同一题 done，没有进入下一题 |
| done 空格按住再松开 | 按住时仍 done、原用时 19.09、pressing=true；松开才出现下一题 ready、elapsed=0.00 |
| paused 空格按住再松开 | 先在 running 刷新，按原 T21 规则恢复 paused=8.43 秒；按住期间仍 paused=8.43，松手后 running，随后画面 8.60 秒 |
| 焦点在“结束”按钮 | 空格按住期间仍为原 done、pressing=false；松手执行按钮的原生退出操作，回到练习设置，没有被全局计时处理接管 |
| 键盘停表后尚持有输入时点 pad | 观察到仍为 done、同题，没有连进下一题 |

长按期间未出现连续推进；明确的 repeat 分支另外用四阶段 × 20 次事件参数验证。自动化按键长按不能替代所有真实键盘硬件重复速率的验收。

### 失焦和输入重叠的验证边界

尝试通过另一个本地浏览器标签页制造失焦时，该环境返回原页面 visibilityState 仍为 visible，因此**没有把它记作实际 blur/隐藏验证通过**。事件级测试已验证真实监听接线、清 hold 和随后 keyup 不触发，但真实系统切后台/窗口失焦还需用户复核。

工具的重叠 pointer/键盘请求可能按顺序执行，无法据此断言已完成双向物理同时按住的手动验收。双向互斥的代码保护、纯函数判据和键盘停表后不连进已验证；真实设备的双向同时输入仍待验。

## 390 宽 pointer / 触屏路径回归

- 使用同一 `.practice-pad` 的 pointer 处理路径，独立长按约 1.4 秒：按住时 phase=ready、pressing=true、elapsed=0.00；松手后才 running，首次读数约 0.24 秒。
- running 时点 pad：停在 done（17.55 秒），松手后仍原题 done，题数只加一次。
- 按下反馈继续使用原样式，没有改颜色/布局。clientWidth=scrollWidth=390，无横向溢出。
- 以上是桌面浏览器 390 宽 pointer 模拟，**不是真手机触摸**。真机长按、pad 外松手、pointercancel、切后台后松手、pointer/空格双向交叉输入仍需复核，不冒充已测。
